## AI-ассистент с RAG, кешированием и логированием запросов

## 📌 Что это даёт

Система отвечает на вопросы по базе знаний:

- быстрее за счёт кеширования
- точнее за счёт RAG
- с контролем за счёт логирования

👉 Результат:

- снижение нагрузки на API
- ускорение повторных ответов
- прозрачность работы ассистента

---

## 🧠 Сценарий использования

Подходит для:

- внутренних ассистентов (инструкции, регламенты, базы знаний)
- поддержки (ответы на типовые вопросы)
- продаж (работа с продуктовой информацией)

---

## ⚙️ Как работает система

- Пользователь задаёт вопрос
- Проверяется кеш
- Если ответа нет — выполняется поиск в базе (ChromaDB)
- Формируется контекст
- Генерируется ответ через LLM (OpenAI)
- Ответ сохраняется в кеш
- Запрос логируется

---

## 🚀 Реализованные компоненты

### RAG (Retrieval-Augmented Generation)

- Векторное хранилище: ChromaDB
- Эмбеддинги: OpenAI (text-embedding-3-small)
- Семантический поиск

👉 даёт более точные ответы, чем “чистый GPT”

---

### Кеширование

- Хранение ответов в `cache.json`
- Ключ — хеш запроса

👉 эффект:

- ускорение повторных ответов (мгновенно)
- снижение затрат на API

---

### Логирование (ключевой элемент)

Все запросы сохраняются в SQLite (`logs.db`)

Фиксируются:

- запрос пользователя
- ответ системы
- источник (RAG / cache / команда)
- время ответа
- использование кеша

👉 даёт:

- контроль работы ассистента
- возможность анализа
- основу для масштабирования

---

### Метрики системы

Команда `stats`:

- количество запросов
- попадания в кеш
- среднее время ответа
- объём базы

👉 позволяет оценивать эффективность системы

---

## 🧠 Пример работы

Запрос:

```
Что такое Python?
```

Первый ответ:

- поиск через RAG
- время ответа ~3–4 сек

Повторный запрос:

- ответ из кеша
- время ответа ~0 сек

👉 ускорение в 10–50 раз

---

## 💡 Доступные команды

- `cache` — показать кеш
- `clear_cache` — очистить кеш
- `stats` — статистика
- `exit` — выход
